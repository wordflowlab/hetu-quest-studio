# 工作流程

设计旧站送信任务：先取信，再消耗一张车票到站，最后交信。比较有票和缺票路线，保存试玩，改条件后复核旧路线。

## 专业判断

变量为有界整数或0／1标记，条件与效果引用明确变量；重复效果、越界初值和悬空引用拒绝。转移先核验当前阶段和全部守卫，再原子应用效果；循环允许但试玩和状态搜索有界。路线固定变量、阶段和转移组合摘要，改条件后旧路线不能当当前试玩。试玩记录保存完整专业快照与程序计算的轨迹，旧记录不覆盖，不能提交伪造状态。状态搜索达到预算返回无法判断，不把未搜到当不可达。

互动叙事拥有分支文本、存档和故事试玩，本包专注任务条件、资源效果与状态可达性。游戏引擎拥有运行时资源、联网玩家和正式游戏发布；本包不提供战斗平衡认证、在线运营或任意脚本执行。

## 返工与恢复

先读取全部相关记录与明确范围，再核对目标摘要。旧依据待复核时保留历史，不将过期记录定位到新稿；只对作者要求的专业操作执行。每阶段回读固定修订，unknown先沿原操作查询，same-key/different-input拒绝；不能用新键掩盖失败或换稿。

## 下游接续

BasisRef不是宿主SourceRef。create_handoff返回固定专业工程后，经公开资料任务保存派生快照，记录Owner、对象、修订、sha256、包摘要和真实专业内容，原工程继续拥有事实。下游参考稿任务固定原材料与派生快照，从task_context回读完整字节后再提交参考稿。独立剧本和视频各自发现、获权与读取；不合并授权，不采纳正文或定稿。

Yarn Spinner与Ink将条件、状态和叙事分开。本包研究其确定性状态语义，独立实现有界任务模型，不声称Yarn／Ink格式兼容、不复制游戏运行时，也不把纯图可达当状态可达。
