# 产品需求

## 背景与推导

游戏任务的合理性既取决于叙事，也取决于玩家当时拥有的条件。图上有路径不证明状态允许通过，一次试玩也不能代表所有路径。工程保存条件和效果，确定性回放具体路线，并在预算内探索可达状态；Agent设计体验，作者判断动机与选择的意义。

生成成本和等待时间会变化，但固定作品、历史依据、具体意见与连续审阅仍需长期积累。固定工程避免让模型每轮重建结构；结构化数据与多种阅读方式共用同一专业成果。插件按需安装，让作者提出目标、Agent操作工程、作者在适合的工作面阅读和选择。

## 定义与首版

游戏任务工坊是河图洛书JS／TS专业插件。把任务前提、状态变量、选择代价和固定试玩轨迹变成可检查、可继续创作的任务工程。用户包括独立作者、编辑与外部Agent。默认旅程：读取固定故事依据 → 任务阶段与有界变量 → 条件与选择代价 → 核对状态可达性 → 固定路线试玩 → 改条件后复核 → 任务本及固定轨迹。

首版包含完整专业维护、准确来源回读、并行方案、固定意见、专业状态和改稿影响、上下文、固定交接、JSON／Markdown／HTML工程及专业阅读本。功能必须经机器入口执行，作者可以自然语言提出目标，也保留人工优化入口。

## 边界

互动叙事拥有分支文本、存档和故事试玩，本包专注任务条件、资源效果与状态可达性。游戏引擎拥有运行时资源、联网玩家和正式游戏发布；本包不提供战斗平衡认证、在线运营或任意脚本执行。正文、正式设定、素材、采纳与定稿由宿主和作者掌握，不另建数据库、模型渠道或内部Agent。

成功以真实创作、审阅、返工及下一轮接续为准，安装、动作数或文件存在都不足以代表完成。开发与验收状态只由08维护。
